## Причины, по которым что-то не реализовано

### 1. API-тесты (сценарии №35–42) не написаны

Из-за ограничений по времени и проблем с инфраструктурой (смена сервера) приоритет отдан UI-тестам, которые проверяют полный пользовательский путь.

### 2. PostgreSQL не проверялся

SUT поддерживает как MySQL, так и PostgreSQL, но прогон сделан только на MySQL. Для полной проверки нужно:
- перезапустить SUT с `-Dspring.datasource.url=jdbc:postgresql://...`;
- прогнать тесты с `-Ddb.url=jdbc:postgresql://...`.

### 3. Allure не настроен

Приоритет отдан работоспособности автотестов и Gradle-отчёту.

### 4. Шесть UI-тестов валидации требуют доработки

SUT показывает ошибку **под полем** (`.input__sub`), а тест ищет всплывающее уведомление (`.notification_status_error`). Поля «Номер карты» и «CVC/CVV» ограничивают ввод маской, поэтому часть тестов не может ввести данные.

### 5. Часть сценариев кредита и оплаты не реализована

Из 17 сценариев оплаты и 17 сценариев кредита реализовано по 2–4 ключевых (APPROVED, DECLINED, часть валидации). Полный охват требует больше времени.
